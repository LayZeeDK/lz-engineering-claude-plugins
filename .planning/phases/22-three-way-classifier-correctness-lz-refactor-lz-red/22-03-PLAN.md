The lettered form is not cosmetic: it is what makes the parse deterministic and the guard mutation-sensitive.
- **D-02:** The post-green what-now request gets its OWN positive lz-refactor branch (newly green and asking what is next is the refactor step's trigger), never a fallback. An add-or-change-behavior request with nothing failing yet routes to lz-red first, because Law 1 forbids production code before a failing test, and to lz-tpp only once a red test is in play. Law 1 is the authority for the first hop and is `Owned; oracle-verified` in this repo's own distillation; do NOT claim book backing for the handoff framing, which that file labels an orchestration reframe.

- **D-04:** Test code is owned by the ask, not the file's kind. A test-quality ask (is this a good test, what should it assert, how should it be named, what test comes next) is lz-red's. A structure-only tidy of code that happens to live in a test file is lz-refactor's. lz-refactor's structure branch gains the explicit exclusion.
- **D-05:** All three skills are in scope, but lz-tpp's edit is minimal and classifier-only.
- **D-06:** Each description is minimally reworded so it names the correct destination -- specifically lz-refactor's trailing exclusion clause, which currently sends an add-or-change-behavior request to lz-tpp even when nothing is failing yet, which lz-tpp declines by its own description.
