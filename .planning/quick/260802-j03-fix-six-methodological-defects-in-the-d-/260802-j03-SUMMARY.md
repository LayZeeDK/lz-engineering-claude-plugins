## Measured findings

These are the things the plan asked to be reported as findings rather than buried.

### The `blunt` fixture returned `blunt_red`. The flagged risk did not materialise.

The plan flagged one risk it could not retire: the runnable fixture might grade `genuinely_red`
if vitest echoed the spec's assertion into `failureMessages`, which would mean `ASSERTION_RE` was
matching the model's own source.

MEASURED, before the predicate existed: the fixture graded **`wrong_reason`** -- the D-05 defect,
reproduced on runnable code. After the change it grades **`blunt_red`**.

The reason the risk did not fire is itself a measurement worth recording. For this shape vitest
4.1.10 emits **no code frame at all** in `failureMessages` -- the message plus ten `at ` frames and
nothing else:

```
Error: correlationId is not implemented
    at correlationId (.../fixtures/blunt/module.ts:12:9)
    at .../fixtures/blunt/module.spec.ts:6:12
    at file:///.../node_modules/@vitest/runner/dist/chunk-artifact.js:302:11
    ...
```

So `ASSERTION_RE` had nothing to match and the pre-change rule fell through to its fail-closed
default. No `ASSERTION_RE` looseness needed recording, and nothing was tuned to reach agreement.

### The inlining introduces a length confound, and it is unavoidable

MEASURED `SKILL.md` lengths: baseline **167** lines, forcing **174**, treatment **282**. The
treatment body is 69% longer than the baseline, on every run. Any measured treatment effect is
therefore confounded with length and position, and treatment-versus-forcing is not a clean
two-lever comparison on length either. You cannot both guarantee the dose and hold length constant,
so this is a declared limitation rather than a defect to fix. It is recorded in
`build-treatment.mjs` and in `AMB1.treatment_arm_question_note`.

Related and also recorded: arm 2 no longer answers "does the reference get used and help". It
answers "does the content help WHEN GUARANTEED PRESENT".

### The verdict corpus is now two-regime, and re-grading history is unnecessary

Widening `verdictPass()` means the 46 archived apply grades were computed under the old
single-passing-class rule, so a verdict column mixing pre- and post-2026-08-02 grades is not
homogeneous. History is deliberately NOT re-graded: the number that carries downstream is the
42-in-44 EMPTY base rate in `AMB2.ceiling_note`, and that is a `changed_production_files` count,
which a verdict-class change cannot move. Declared in the grade-red header and in
`AMB1.throw_variant_hazard`.

### `a2` is exempt, and the reason is recorded so nobody "fixes" it

`a2`'s resolving clause is the only thing in its prompt that introduces a collaborator at all.
Remove it and "Stub that" has no collaborator referent left, so the only nameable artifact is
`src/log.ts` -- the SUBJECT -- and the natural reading shifts toward the production side, which is
that cell's WRONG answer. The cut would not create ambiguity; it would invert ground truth. `a2`
also has no headroom: its correct signature is EMPTY and the corpus base rate for EMPTY is 42 in 44.
Recorded in `AMB2.ceiling_note`. Byte-identity asserted (`git diff --quiet` exit 0).

### D-02's scope limit

`clean -fd` has no `-x`, so ignored content (`node_modules/`, `dist/`) persists across runs by
design and by necessity -- a fresh worktree per run is explicitly declined. The `pristine` record
therefore proves the TRACKED tree was pristine, **not** that the environment was fully isolated.
That is the honest claim and it is the one the code makes.

### The blunt-red predicate's stackless residual

A message carrying no `at ` frame at all -- a custom Error with its stack stripped, or a runner
reporting message-only -- cannot have its origin established, so it fails CLOSED to `wrong_reason`.
Some genuine blunt reds will still be mis-scored. That is the correct direction and it is stated in
the predicate's docblock rather than engineered away.

## How the risky change was kept one-directional

The assertion test is byte-identical to the pre-change rule and still runs FIRST; the blunt-red path
runs only where the old rule already said no. So no input that graded `genuinely_red` before can
grade anything else now. `RUNTIME_RE` is a hard veto evaluated first, over the whole message.
Condition 1 reads frame 0 only (runner-attested -- the model cannot make V8 name a file it did not
execute in); condition 2 reads the message HEAD only, after `stripCodeFrame`.

The canary runs BOTH rules on identical inputs, six rows:

| # | Case | New rule | Pre-change rule |
|---|---|---|---|
| a | the CAPTURED blunt red from `invoke_forcing`/`a1`/`run-1` | `blunt_red` | `wrong_reason` |
| b | runtime token AND the phrase in the head, frame 0 in the added production file | `wrong_reason` | `wrong_reason` |
| c | a library's own not-implemented throw, production list non-empty | `wrong_reason` | `wrong_reason` |
| d1 | the phrase only in the runner's code-frame echo | `wrong_reason` | `wrong_reason` |
| d2 | the phrase only inside a stack-frame FUNCTION NAME | `wrong_reason` | `wrong_reason` |
| e | one blunt red plus one genuine TypeError | `wrong_reason` | `wrong_reason` |

Case (a) is asserted to DISAGREE; (b)-(e) are asserted to AGREE. (d1) and (d2) additionally assert
that `NOT_IMPLEMENTED_RE` DOES match the whole message, so neither can rot into decoration -- only
the slicing keeps them out.
