# Phase 22.1 Plan 01: Resumable eval run-set core with both backends and the D-03 dry run Summary

**tools/evals runs `claude plugin eval` once per run and slim `claude -p` through run-slim with resume, marks a run done only by a harness-written result.json after limit and model checks, and passes the stub dry run killed partway on Node 22, 24 and 26.**

- **Duration:** 25 min (06:58Z to 07:23Z)
- **Tasks:** 3 of 3

## Accomplishments

- Run-set core (`run-set.ts`): `readRunSet` validates names, 40-hex refs, run counts and recorded cells; `planRuns` expands cells and honours `recheck.json`; `runState`, `newRuns`, `diedRuns`, `setAside`, `writeResult` (temp file then rename), and `runAll`, which takes no new run after a usage-limit outcome.
- plugin-eval backend: the argument order from RESEARCH Pattern 2 (target first, `--allow-tools` last), traces copied into `raw/` before any check, and `normalizePluginEval` sorting complete, partial, limit, max-turns, other-error, missing-JSON, missing-trace and wrong-model runs.
- slim backend: `slimArgs` with `--rules none`, a fresh per-run working folder below the slim root (deletion refused outside `<slim root>/runs/`), `resumeArgs` into the next `result-resume-<n>.json`, `sessionId` from the latest `--out` or the run's own transcript folder, and `withHeavyLock`, which throws for a heavy suite without `LZ_EVAL_HEAVY_LOCK`.
- aggregate: per-grader k/n, Wilson interval, `recheckCases`, recorded-cell comparison (`case-fired`, `case-quiet`, `run`), a partial line, refusal of mixed case trees, and refusal of stub results without `--allow-stub`.
- CLI `eval.ts`: `run`, `rerun`, `resume`, `aggregate`; every refusal happens before the first spawn.
- The D-03 step 1 free dry run (`dry-run.test.ts`): 24 runs killed partway (5 done, 1 died, 18 new), the next `run` finishes the 18 and names the died run with `rerun`, `rerun` sets it aside in `set-aside-1`, raising Sonnet to 3 adds exactly the 6 run-3 folders with no earlier result.json mtime changed, a killed slim run resumes with `--resume <transcript uuid>`, and a usage-limit stop on both backends leaves `raw/refused.txt`, no result.json and the rest new.
- REQUIREMENTS.md: EVH-01..EVH-12, twelve Traceability rows, coverage 45/45.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Wilson z default**
- **Found during:** Task 2
- **Issue:** the plan names `wilson(passed, total, z = 1.96)` and also requires `wilson(3, 3)` lower bound to round to 0.439. With z = 1.96 it is 0.43849 (rounds to 0.438).
- **Fix:** default z = 1.959964, the exact 97.5% quantile; 13/13 still gives [0.772, 1], 3/3 gives 0.439. The reason is in a one-line comment.
- **Files modified:** tools/evals/aggregate.ts
- **Commit:** aa9c5f9

**2. [Rule 3 - Blocking] `fnm exec ... npm run check` does not run on the requested Node version**
- **Found during:** Task 3 verification
- **Issue:** inside `npm run` and `npm exec`, `node` resolves to `~/.vite-plus/js_runtime/node/26.13.1/node.exe` whatever `fnm exec` selects (measured: `npm exec -c 'node -p process.execPath'` under `--using=22.23.1` printed v26.13.1). The plan's verify commands exit 0 but test on 26.13.1 only.
- **Fix:** ran tsc and `node --test` directly with `fnm exec --using=<v> node ...` for 22.23.1, 24.22.0 and 26.13.0; all green. PATH left unchanged. The plan's literal commands also exit 0.
- **Impact for later plans:** any "run on Node 22 and 24" check in this phase must call `node` directly under `fnm exec`, not `npm run`.

**3. [Rule 2 - Correctness] recheck.json is merged, never shrunk**
- **Found during:** Task 2
- **Issue:** once a case has 5 Opus runs it no longer qualifies for the recheck list; rewriting recheck.json from scratch would drop runs 4 and 5 from the plan and from aggregation.
- **Fix:** `aggregate` merges the new list into the existing file.
- **Files modified:** tools/evals/eval.ts
- **Commit:** aa9c5f9

**4. [Rule 3 - Structure] One shared settle step and some extra exports**
- `Normalized` and `settleRun` live in run-set.ts so both backends write result.json or raw/refused.txt the same way.
