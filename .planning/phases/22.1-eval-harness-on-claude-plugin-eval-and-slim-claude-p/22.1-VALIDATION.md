# Phase 22.1 - Validation Strategy

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `node:test`, run by Node.js directly on erasable TypeScript |
| **Config file** | `tools/evals/tsconfig.json` (none yet -- Wave 0 creates it) |
| **Quick run command** | `node --test tools/evals/<name>.test.ts` |
| **Full suite command** | `npm --prefix tools/evals run check` (tsc, every `.test.ts` named, `check-cases.ts`) |
| **Estimated runtime** | ~30 seconds |

## Sampling Rate

- **After every task commit:** the touched module's `.test.ts` plus `tsc`.
- **After every plan wave:** `npm --prefix tools/evals run check` (Node 26: inside `npm run`, `node` is the vite-plus
  Node 26 whatever fnm selects, measured 2026-11-25), and from `tools/evals`, for X in 22.23.1 and 24.22.0,
  `fnm exec --using=X node node_modules/typescript/bin/tsc -p tsconfig.json` and
  `fnm exec --using=X node --test <every *.test.ts named in scripts.check>`; plus `npm run check` in both
  `.claude/skills/lz-red-workspace` and `.claude/skills/lz-refactor-workspace`.
- **Before verification:** the above, Stryker on `tools/evals` (pinned lz-node-test runner), `claude plugin validate .
  --strict`, the email allowlist scan over committed `evals/` and `RESULTS.md`.
- **Max feedback latency:** 60 seconds.
