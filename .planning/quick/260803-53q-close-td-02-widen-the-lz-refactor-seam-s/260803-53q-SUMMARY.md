# Quick Task 260803-53q: Close TD-02 -- widen the lz-refactor seam to route back to lz-red Summary

The shipped `lz-refactor` router now carries the `lz-refactor -> lz-red` return hop, and a
regression guard in the lz-red battery holds it there. Both edits landed instrument-first: the
guard was authored and measured RED against the real pre-change tree before any prose was written
to satisfy it.

## What changed

**`.claude/skills/lz-red-workspace/tools/check-red-references.mjs`** (Task 1, commit `da17585`)

One post-loop guard, placed immediately after the existing SEAM-02 block it mirrors. It resolves
`plugins/lz-tdd/skills/lz-refactor/SKILL.md`, reads it inside a try/catch that yields the empty
string, tests `/lz-red/`, and calls `report()` exactly once, unconditionally. It is deliberately
NOT existsSync-gated: this file's own header condemns an existsSync-gated post-loop block as a
silent vacuous pass, and empty text has no match, so the guard fails closed with no extra branch.
`EXPECTED_CHECKS` moved 124 -> 125 with its own arithmetic term, and the GREEN `SUMMARY:` line now
names the return pointer so the instrument's output does not overstate what it checked.
`NEW_LABELS` and `RETIRED_LABELS` were not touched, matching the SEAM-02 precedent.

**`plugins/lz-tdd/skills/lz-refactor/SKILL.md`** (Task 2, commit `6b7ac4f`)

The seam section was widened in place, not duplicated. The heading became
`## Refactoring vs the red step (lz-red) and the green step (lz-tpp)`, and the body now states
three owners and routes with one positively-stated branch each. Coach procedure step 1 classifies
against both seams with the same three branches, and its back-reference was moved with the heading
-- it quotes the new heading in full, character for character.

Every branch keys on what the developer is ASKING FOR. Nothing in the file is conditioned on the
absence of a failing test, so a cleanup-on-green request -- this skill's primary use case -- still
routes here. The step 1 stay-here branch was also converted from the old test-state phrasing
("if the tests are green and the code has a structure-only smell") to the intent phrasing, so all
three branches classify on the same axis.
