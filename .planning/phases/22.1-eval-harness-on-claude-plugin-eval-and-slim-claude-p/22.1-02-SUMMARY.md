# Phase 22.1 Plan 02: Staging from git, the grader model, and slim templates Summary

**Every run now tests a git-archived commit with the committed cases, slim runs are graded from their own transcripts by a regex/tool_used model that `crosscheck` holds against the CLI, and slim runs start in a copy of a pinned GildedRose template whose armed tree equals the recorded armed base `6fe2325`.**

## Performance

- **Duration:** about 75 min
- **Tasks:** 3 of 3, plus one fix commit from the Task 3 real check
- **Files:** 7 created, 13 modified

## Accomplishments

- `stage.ts`: `resolveCommit`, `pluginTree`, `casesTree`, `extractTar` (Windows `tar.exe`), `stageRef`. The plugin comes from `git archive <sha>:plugins/lz-tdd`. The cases come from `git archive HEAD:evals/lz-tdd/<suite>` for each committed plugin-eval suite, and two cases with one name are refused. `stage.json` records the sha, both trees and the case names. `plugin/` is reused, and `lz-tdd/` is rebuilt when the case trees change.
- `eval.ts`: `stage <ref>`, `template <name>`, `crosscheck <run set dir>`. `run`, `rerun` and `resume` refuse uncommitted case roots before anything else. They stage every ref their runs need, check each plugin-eval case is in its stage, read the slim graders and build every needed template, all before the first spawn.
- `grade.ts`: `readGrader` refuses `llm`, `file_exists` and any key it does not model. `gradeRun`, `sessionTranscripts` (main plus `subagents/`), `runEvidence` (every session the --out files name, each tool call once, the latest reply) and `crosscheckRunSet`.
- `slim.ts`: a done slim run is graded before result.json is written, and one without a transcript fails ("no transcript for session <id>"). The run folder is filled from the suite's template, and a `case.yaml` scaffold script runs there through bash with PATH, a temp HOME and TMPDIR only, 120 s. Heavy suites already hold the lock across all of `startSlimRun`.
- `templates.ts` and `evals/lz-tdd-apply/templates.json`: the three GildedRose recipes. `buildTemplate` does archive, lockfile sha256, `npm ci --ignore-scripts --no-audit --no-fund` through `npm-cli.js`, arming (update run, plain re-run, blob check), overlay, red proof, then `git init` and commit. `copyTemplate` makes a dereferenced copy into an empty folder below `<slim root>/runs/`.
- `cases.ts`: `readCaseYaml`. A suite's `target` must be a template name, and only on slim suites.
- Plan 01's integration tests (`eval.test.ts`, `run-set.test.ts`, `dry-run.test.ts`) now stage a commit of a temp git repository. The hand-made fake stage is gone.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `casesTree` and the dirty-case refusal cover the case roots, not all of evals/**
- **Found during:** Task 1
- **Issue:** The plan names `git rev-parse HEAD:evals` and `git status --porcelain -- evals`. Run sets live in `evals/results/<set>/` (run-set.json and RESULTS.md are tracked). Under the plan's wording, an aggregate's RESULTS.md would block the next `rerun`. Committing it would change casesTree for later runs, and `aggregate` then refuses mixed case trees for the arm.
- **Fix:** casesTree is `<HEAD:evals/lz-tdd>+<HEAD:evals/lz-tdd-apply>` (`none` for a missing root, plain `none` when both are missing). The refusal runs `git status --porcelain -- evals/lz-tdd evals/lz-tdd-apply`. templates.json and the overlays sit under lz-tdd-apply, so they are covered.
- **Files modified:** tools/evals/stage.ts, tools/evals/eval.ts
- **Commit:** 94b0edd

**2. [Rule 2 - Correctness] Slim graders are read before the first spawn**
- **Found during:** Task 2
- **Issue:** The harness grades a slim run after the session has been paid for. A grader the model cannot read would only fail then.
- **Fix:** `run` calls `readGraders` on every slim case it is about to start.
- **Commit:** d7ac2b7

**3. [Rule 1 - Bug] The armed template failed: `ts-node` not found**
- **Found during:** Task 3 real check
- **Issue:** `test/vitest/approvals.spec.ts` runs `execSync('ts-node ...')`. That works under `npx vitest`, which arm-anchor.mjs used and which puts `node_modules/.bin` on PATH. The plan's direct `process.execPath node_modules/vitest/vitest.mjs` spawn does not.
- **Fix:** `withLocalBin` prepends `<template>/node_modules/.bin` to the child's PATH, keeping the key the environment uses (`Path` on Windows). Failed runs now report the runner's output tail through `TestRun.output`. The user's PATH is unchanged.
- **Files modified:** tools/evals/templates.ts, tools/evals/templates.test.ts
- **Commit:** 4898a59

**4. [Rule 3 - Structure] Small placement choices**
- The template marker is `<template>/.git/template.json`, not `<template>/template.json`, so `copyTemplate` carries no untracked file into a run folder.
- `outFiles` moved from slim.ts to trace.ts, so grade.ts and slim.ts share it without an import cycle.
- `copyTemplate(dir, cwd, slimRoot)` takes the slim root to check the run folder against.
- `Trees` (run-set.ts), `SlimMeta`, `RunMeta extends Trees` and context `trees`/`templates`/`projectsDir` carry the tree hashes and templates into both backends. `settleSlim` gained a `projectsDir` parameter.
- `gitIn`, `git`, `archiveInto`, `readStage`, `readGraders`, `traceEvidence`, `templatesFile`, `kataToolchain`, `withLocalBin`, `bashOf`, `runScaffold` and `scaffoldScript` are exported beyond the plan's lists. All planned names are kept.
- `template <name>` also refuses uncommitted case roots, because it reads templates.json and the overlays.
- `crosscheck` counts agree and disagree per grader verdict and unchecked per run arm. An arm with no CLI verdicts is skipped.
