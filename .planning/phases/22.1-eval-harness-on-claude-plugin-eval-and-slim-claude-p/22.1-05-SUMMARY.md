## Compound-Bash call

This was the plan's call, then changed by the brief update Lars approved on 2026-11-25. His words, replying "1: OK"
to the recommendation "Run all slim evals with the dedicated permission set (`--offline` plus each suite's own
list)? My pick: yes, always on, starting with Plan 05, which I'd re-brief to use Bash rules instead of the PowerShell
ones."

Every apply suite (six GildedRose suites and the two srvx suites) now allows:

`Edit Write Read({plugin}/**) Bash(npx vitest:*) Bash(npx tsc:*) Bash(npm test:*) Bash(npm run:*) Bash(cd:*) Bash(grep:*)`

and the srvx suites add `Bash(pnpm vitest:*) Bash(pnpm exec:*) Bash(pnpm test:*) Bash(pnpm run:*) Bash(pnpm typecheck:*)`.

| Rule | Why |
|------|-----|
| `Read({plugin}/**)` | The pilot's one plugin-reference refusal: the skill could not open its own reference outside the run cwd. The harness expands `{plugin}` to the staged plugin folder as `//d/...` and drops the rule in the no-plugin arm (96c197f). |
| `Bash(cd:*)` | 7 of 10 pilot apply runs had compound commands that start `cd <cwd> && ...`. |
| `Bash(grep:*)` | Pilot pipelines ended `\| grep`. Caveat (read from run-slim's `slimPermissions`, not measured in a run): run-slim keeps the maintainer's deny list in offline runs too, and that list denies `Bash(grep *)`, so this allow rule is shadowed while that deny stands; `rg` is in the offline set. |
| dropped `Bash(tail:*)` | The offline set already allows `Bash(tail *)` (and `cat`, `head`, `rg`, read-only git). |
| dropped `PowerShell(npx tsc:*)`, `PowerShell(npx vitest:*)` | The offline set denies the PowerShell tool, so they could never apply. |
| no redirection rule | Claude Code checks a redirect target as a file write against Edit rules, and the suites already allow bare `Edit`, which covers a target inside the run cwd. No Bash rule form grants a redirect by itself. Inferred, not measured: Plan 06's first runs should check `permission_denials` for redirects. |

`slimArgs` passes `--offline` on every run and resume, test-first (6c4a08e). The stub run's logged argv showed
`--offline` and the expanded allow list.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] A suite allow list could not name the staged plugin folder**
- Found during: Task 1 (pilot finding to carry)
- Fix: `{plugin}` in a suite's allow list expands to the staged plugin folder as a `//d/...` rule path, and its rules
  are dropped with no plugin.
- Files: tools/evals/slim.ts, slim.test.ts. Commit: 96c197f

**2. [Rule 1 - Bug] A cleanup failure hid a failed template build's own error**
- Found during: Task 4, first real srvx build. The build crashed, then removing the half-built folder threw EPERM,
  and only the EPERM reached the caller.
- Fix: cleanup retries. If the folder still cannot be removed, the error gives the build failure first and then the
  folder left behind. The test holds the folder with a running child process, which reproduces the same EPERM.
- Files: tools/evals/templates.ts, templates.test.ts. Commit: 97a203d

**3. [Rule 1 - Bug] A template on Windows lost the clone's exec bits**
- Found during: Task 4. The template tree had `bin/srvx.mjs` as 100644, so it differed from the pinned tree.
- Fix: after staging, every 100755 entry of the clone's tree is marked executable again. The test fixture gained an
  executable file. GildedRose has none, so its templates are unchanged.
- Files: tools/evals/templates.ts, templates.test.ts. Commit: 31de1ac

**4. [Brief change] Offline permission set, Bash-only apply rules**: see Compound-Bash call. Commits: 6c4a08e, ddde852

**5. [Pilot evidence] edited-test instead of wrote-test**
