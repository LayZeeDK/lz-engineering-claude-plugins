## Case format (claude plugin eval, RESEARCH F1 "Case fields" and Pattern 4; lz-oop cases are the measured shape)

- `<suite>/suite.json` (harness only, Plan 01 `readSuite`), `<suite>/<case>/prompt.md` (frontmatter + the prompt
  body), optional `<case>/case.yaml` (`schema_version: "1.1"`, `name`, `tags`, `context:` / `scaffold_script:
  scaffold.sh`), `<case>/graders/<name>.md` (frontmatter + one line saying what it checks).
- `prompt.md` frontmatter keys the `plugin eval` loader accepts (measured 2026-11-25 by a free loader probe; an
  unknown key fails at load time, before any run): `schema_version`, `name`, `description`, `tags`, `plugins`,
  `runs`, `expected_outcome`, `model`, `max_turns`, `timeout_seconds`, `allowed_tools`, `disallowed_tools`,
  `artifact_publish`, `growthbook_overrides`, `append_system_prompt`, `env`. Of these, `model` and `runs` are refused
  too: the harness passes them per run (D-02, D-10). The cases in this phase use `tags`, `max_turns`,
  `timeout_seconds` and `allowed_tools`.
- Grader keys here: `type` (`regex` | `tool_used`), `pattern`, `flags`, `tool`, `input_match`, `min`, `max`, `arm`.
- Skill-fired `input_match`: `'"skill"\s*:\s*"(?:[\w-]+:)?<skill>"'`. Quiet: the same with `min: 0`, `max: 0`,
  `arm: both`. File paths in `input_match` use `[\\/]+` between segments (JSON-encoded Windows paths, Pitfall 5).
- Phase 23 D-05 report lines (regex on the last message, no `m` flag so `$` is the end of the reply): RED
  `'RED: [^\n]+ -- fails: [^\n]+\s*$'`; REFACTOR `'REFACTOR: ([^\n]+ -- tests green|none -- [^\n]+)\s*$'`; GREEN on
  plugin eval (no Bash there, Pitfall 6) `'GREEN: [^\n]+ -- [^\n]+ passes[^\n]*\s*$'`; GREEN on slim
  `'GREEN: [^\n]+ -- [^\n]+ passes; \d+ tests green[^\n]*\s*$'`.
- Suite.json gains `skill` (the lz-tdd skill under test, or null) in this plan.
