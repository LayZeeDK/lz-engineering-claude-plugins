The AWS Lambda adapter decides whether a response body is text or binary from its content type, and it gets it wrong both ways: `application/octet-stream; charset=utf-8` gets decoded as UTF-8 and the bytes are corrupted, while `image/svg+xml` and `application/ld+json` get base64-encoded for no reason. Fix the text/binary detection.

Fix it test-first with the lz-tdd plugin. The tests live in test/aws.test.ts; run them with `npx vitest run test/aws.test.ts`.
