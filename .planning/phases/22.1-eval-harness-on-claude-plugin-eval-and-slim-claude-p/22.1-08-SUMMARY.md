## Deviations from Plan

**1. [Brief] Trigger turn cap and tools (Lars 2026-11-26).** port-cases.ts writes `max_turns: 10` and
`disallowed_tools: [Agent]` into all three trigger suites; trigger-lz-tpp-turns10 deleted in the same commit
(b942312).

**2. [Brief item 5] srvx on npm, proven free before paying.** The srvx recipe gains `npm: true` (34e7093): pnpm files
removed and package scripts that call pnpm rewritten to npm, test-first in templates.test.ts. The built template
then had 3 typecheck errors from @types/node 26.6.10; pinning 26.1.1 in the npm lockfile (8e0349b) brought them to 0,
and `npx vitest run test/node-adapters.test.ts` passed 74 tests, before any paid run. Plan step 8's `LZ_EVAL_PNPM`
no longer applies.

**3. [Rule 3] `--lock-note` (20061f7).** The slot's task names the lock part, so peers see which part holds the slot.

**4. [Process] Lock parts held by a launcher, plus a guard.** Each part ran from a scratch launcher that waits,
acquires the timing-sensitive slot, waits until busy cores drop to 1.5 or 60 s pass, logs free memory, starts a
guard, runs `eval.ts rerun` on the named run folders with a no-op lock, and releases. Parts were booked from measured
rates plus a quarter, at most 20 min.

**5. [Bug, mine, fixed] The guard killed eval.ts.** Three eval.ts deaths (02:44, 03:10 and 03:21 local) came from the
guard: its regex took `..., pid N` as the slot end, the parse failed, `$end` stayed `$null`, and PowerShell's
`UtcNow -ge $null` is true, so it stopped the part as soon as anyone joined the waiting list. Fixed (exact holder
line, TryParse, never stop on an unparsed time); afterwards it stopped part 4 correctly at its slot end. The earlier
suspicion of a peer's `taskkill` was wrong (inferred from the timing).

**6. [Process] Scaffold failures under PowerShell.** Launched from pwsh, `bash` resolved to the WSL bash and 5
doing-lz-red Sonnet scaffolds failed; parts launched from Git Bash afterwards. The 5 folders were set aside and rerun.

**7. [Harness behaviour] A flagged run stays.** apply-lz-red-r1 Sonnet run 1 overlapped a peer-load window (73 s
against 27-35 s). `rerun` refuses to replace a finished result, so RESULTS.md flags it instead.
