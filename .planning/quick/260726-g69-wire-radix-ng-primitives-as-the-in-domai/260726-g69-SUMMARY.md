## `escapingLinks`: what the boundary change catches and what it permits

The signature is now `escapingLinks(root, boundary = root)`. `root` is still the tree WALKED;
`boundary` is what each resolved link target is compared against. The default keeps both pre-existing
call sites behaviourally identical (the checker confirmed there are exactly two). `gradeRun` walks
each copied destination with the **worktree** as the boundary, once, AFTER every path is copied --
order is load-bearing, since package-level links resolve into the root copy.

**Now PERMITTED:** a link inside the copied toolchain that resolves anywhere else INSIDE the same
grading worktree. Measured on the pinned radix tree: 8,164 symlinks, 100% relative, ZERO absolute,
ZERO resolving outside the repo -- of which SEVEN escape their own copied root and NONE escape the
worktree. Six are `packages/primitives/node_modules` links pointing up into the root store; the
seventh is the root store's workspace self-link
(`node_modules/.pnpm/node_modules/@radix-ng/primitives -> packages/primitives`), which fires even on
a single-path copy. Both link shapes were confirmed relative by direct inspection.

**Still CAUGHT, unchanged:** an ABSOLUTE link into the source checkout, an unreadable link, and any
`..` chain that leaves the worktree. crux 9 asserts BOTH boundaries over ONE synthetic pnpm-shaped
tree, so the widening is proved to be a widening and not a removal: the narrow boundary reports the
legitimate up-link (the pre-change rule) and the worktree boundary does not, while the absolute
escape is reported under BOTH.

This is a CORRECTION, not a relaxation -- the guard's own header always said the hole it closes is
"a link escaping the WORKTREE leads back to the borrowed repo"; the boundary it compared against was
simply narrower than its stated contract.

## Deviations from the plan

### 1. `fs.cpSync` needed `verbatimSymlinks: true` -- a genuine bug the guard caught (Rule 1/3)

**Not in the plan, and it falsifies a "do not re-litigate" fact in the brief.** TARGETS.md section 2
states "`fs.cpSync` preserves symlinks VERBATIM by default (verified directly)". It does not.

Found end to end rather than by reading: the FIRST real radix grade in the battery failed with
`8,170 link(s) resolve outside <worktree>`, every one of them pointing at
`D:/projects/github/radix-ng/primitives-pin/node_modules/.pnpm/...`. Root-caused by direct
measurement on a synthetic tree: with the default `verbatimSymlinks: false`, `fs.cpSync` resolves
each relative link against the SOURCE directory and writes the resulting ABSOLUTE path into the copy.
A relative `../store/pkg` link copies as `<source>/store/pkg` under the default and as
`../store/pkg` under `verbatimSymlinks: true`.

So the per-grade copy was silently becoming a live path back into the borrowed repo -- the exact hole
the copy exists to close (T-63f-05), reopened by an option default. **The guard did its job**; this
is a bug fix, not a guard being appeased.

Fixed in `copyToolchainPaths` with a comment recording the measurement. The fail-closed direction is
unchanged: an ABSOLUTE link in the SOURCE is preserved as absolute, still points outside, and is
still reported as an escape. Discrimination proved two ways on identical inputs -- directly (default
vs verbatim on the same synthetic tree) and by the end-to-end failure -- and crux 9 now asserts that
a copied relative store link resolves inside the destination. No flag was added.

Landed in commit 3 rather than commit 2 deliberately: commit 2 is green on its own battery (no target
declared `toolchain_paths` yet, so behaviour was byte-identical), and commit 3 is the first commit
where a symlinked toolchain is actually copied. Every commit stays green and bisect-safe.

### 2. The boundary probe's up-link is a junction on Windows, and the comment now says so

`fs.symlinkSync(..., 'junction')` always stores an ABSOLUTE path on Windows, so describing the crux 9
probe's up-link as "RELATIVE" would have been inaccurate. The probe now uses a `linkDir()` helper
that writes RELATIVE text where the platform allows it (it does here) and falls back to a junction
otherwise; either way the link resolves inside `wt` and outside `pkgNm`, which is the property under
test. The comment states the fallback rather than implying a guarantee.

### 3. RUN-GATE's ngx-layout section was collapsed, not deleted outright

The plan said to REPLACE the blocked-target subsection with a one-paragraph CLOSED note. Done -- but
a compact cost record was kept below it, because a residual bullet still cites its 27%
intra-vs-cross-volume number and deleting it would have left a dangling reference. Net: 77 lines to
