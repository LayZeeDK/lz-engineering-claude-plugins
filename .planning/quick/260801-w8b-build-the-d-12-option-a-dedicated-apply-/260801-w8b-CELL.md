1. **Coach-don't-drive.** `SKILL.md:99-100` says lz-red "no longer has to author a wrong-value
   production-side stub" and leaves "who owns that production-side stub" **explicitly UNSETTLED**. A

   into an axis already being measured"), and on `a1` it is a partial collapse rather than a total
   one: the correct answer keeps the test RED, so it is separable from `drove_to_green`, but it is
   not separable from a general willingness to touch production.
2. **The answer is in the baseline's worked example.** See the fifth kill above.

### Where this disagrees with `260801-w8b-AMBIGUITY-FEASIBILITY.md`

That doc's section 4 disqualified the axis-1 cell: "production-side stub + failing test grades
`genuinely_red` `pass:true`, so the *wrong* reading also passes. Ground truth not separable."

**That objection is about the VERDICT and it does not apply to this design**, which discriminates on
`changed_production_files` and treats the verdict as secondary. The verdict is deliberately blind

What I did NOT overturn is that doc's core structural finding. I agree with it. I am reporting that

## Target selection and why

Required for `a1`: a production symbol that genuinely does not exist, that is the SUBJECT rather than
a collaborator, whose placeholder body leaves the added test failing on an ASSERTION.
Required for `a2`: an existing subject, a real collaborator in the way, an ALREADY-EXISTING seam so a
test-side substitute needs no production change, and a genuine behaviour gap so the correct test is
red at all.

**Chosen: srvx** (`D:/projects/github/h3js/srvx`, pinned at `55d90b39` = v0.12.4), the existing
`e2e-red-srvx` suite, two new targets `AMB1` / `AMB2`.

Why srvx over the other two vendored options:

- **Gilded Rose is unusable for `a2`.** The kata is two classes with no IO, no clock and no
  collaborators of any kind, so "a real collaborator is in the way" cannot be constructed there
  honestly. It is also HIGH contamination.
- **radix-ng is usable but three times the price and a worse fit.** Its measured grading cost is
  ~35 s of toolchain copy plus ~19 s of atc per grade (targets.json, measured 2026-07-26), against
  srvx's measured 2.5 s copy and 3.5 s prebuild in this session's selfcheck run. And `a1` there means
  authoring a new Angular directive or service as a placeholder, which is a much heavier artifact
  than a middleware.
- **srvx carries BOTH senses of the contested word in its own tree**, which is the property that
  makes the ambiguity locally genuine rather than imported: `StubNodeServer` / `nodeServerStub` are
  production-side (`src/loader.ts:236-283`), while `test/log.test.ts:80` calls a fabricated response
  object one, test-side. Neither reading is alien to this codebase, so the repo does not silently
  resolve the prompt in either direction.
- srvx also has the cheapest real toolchain of the three and both prompts land in one collection
  root (`test/`), so the existing `crux 7:SRVC` canary pair licenses both new targets with no new
  fixture.

Neither prompt reuses SRVC's dropped-header defect (kill 2). `a1` uses a symbol that does not exist;
`a2` uses an unlogged failure path in `src/log.ts`.

**Why one suite, not two:** `walkAllSuites` throws only when a SECOND suite claims a cell key, so
`AMB1:a1` and `AMB2:a2` inside `e2e-red-srvx` are free, and sharing SRVC's repo/pin/runner/typecheck
means the existing canaries already prove the plumbing.

## `a1` in full

**Exact text:** see above.

**The two competing readings of the bare word:**

- **Production side (CORRECT).** Add the middleware to the shipped tree with a correct signature and
  a placeholder body, then add a test that asserts the real behaviour and fails.
  `changed_production_files` NON-EMPTY.
- **Test side (WRONG).** Stand the middleware up inside the spec, or `vi.mock` a module that is not
  there, and add nothing shippable. `changed_production_files` EMPTY. Its close cousin: write the
  spec against the missing module and treat the module-resolution failure as the red. Also EMPTY, and
  additionally grades `compile_error`.

**Why the ground truth is determinate:**

1. The thing the developer names is the SUBJECT. Nothing here is a collaborator, so on the artifact's
   axis 2 this is "the symbol's OWN unwritten implementation", which the census places in
   Production/own/transitional (Beck) with no hedge. The one cell the artifact refuses to adjudicate
   -- `Temporary Test Stub`, a collaborator nobody has written yet -- is a different cell.
2. A test-side double of the subject is tautological. You cannot drive the design of a thing by
   substituting that thing.
3. The developer asked for **both** ("Stub it AND add the failing test"). A test-only turn answers
   half the request regardless of how defensible test-first orthodoxy is in the abstract.

**Why a capable model might get it wrong without the artifact:** the strongest reflex for a
not-yet-existing symbol is "write the test first, let it fail, write no production code before red".
That is orthodox TDD, it is what the corpus baseline actually does (2 production touches in 44 runs),
and it leaves the discriminator EMPTY. lz-red's own step 6 reinforces the reflex and explicitly
leaves ownership of the production-side stub unsettled.

**Measured, this session, in the pristine clone at the pin:**

| Fact | Method | Result |
|---|---|---|
| The symbol is absent | `git grep -in correlation` repo-wide | zero hits; the only middleware exports are `loggerMiddleware` (`src/log.ts:206`) and `staticMiddleware` (`src/static.ts:215`) |
| The correct answer is ASSERTION-red | pass-through placeholder typed `ServerMiddleware` + a one-line-title spec, `npx vitest run <spec> --typecheck.enabled=false --reporter=json` | exit 1, `numTotalTests` 1, `numFailedTests` 1, `assertionResults[0].status` "failed", verbatim `AssertionError: expected null to be truthy` |
| It matches the classifier | `ASSERTION_RE` / `RUNTIME_RE` at `grade-red.mjs:84-89` | matches ASSERTION, matches no RUNTIME token, so `classify()` returns `genuinely_red` |
| The differential stays clean | `npx tsc --noEmit --strict --skipLibCheck` with the placeholder and both specs present | exit 0, so ZERO new errors |
| A new `src/` file cannot break the prebuild | read `build.config.mjs` | obuild is driven by an EXPLICIT 15-entry `input` list; an unlisted src file is never built |

**Why a middleware and not a plain helper:** a middleware's natural placeholder body is a
pass-through, which is assertion-red. A plain helper's natural placeholder is a not-implemented
throw, which grades `wrong_reason`. Choosing the shape that satisfies the hard requirement was
deliberate, and the throw variant is recorded as a hazard rather than designed away (see below).

## `a2` in full

**Exact text:** see above.

**The two competing readings of the bare word:**

- **Test side (CORRECT).** Replace `process.stdout.write` from inside the spec, drive the middleware
  directly with a fabricated request and a throwing downstream, assert a line was written.
  `changed_production_files` EMPTY.
- **Production side (WRONG).** Add a writer / sink / stream option to the middleware's options so
  stdout can be injected, then test through the new option. NON-EMPTY. Its cousin: emit the missing
  line, which makes the test pass and grades `drove_to_green`.

**Why the ground truth is determinate:** the seam already exists, and that is measured rather than
reasoned. `src/log.ts` captures `const stdout = globalThis.process?.stdout` at module load but calls
`stdout.write(chunk)` per line, so the property lookup is late and a test-side swap intercepts every
line. Widening a shipped API to serve a test when a seam already exists is over-reach, and
`test/log.test.ts:52-56` already does the swap, so it is also the house pattern.

**Why a capable model might get it wrong without the artifact:** read `src/log.ts` on its own and the
writer looks unseamable -- it is a module-private `const` resolved inside an IIFE at import time. The
tidy-looking move is to add one more option next to `batch`. Models reach for dependency injection
for testability readily.

**Measured, this session, as a DISCRIMINATING PAIR** (a single red would not prove why it is red):

| Probe | Result |
|---|---|
| THROW path: stdout swapped from the test, `next` throws, assert one line written | exit 1, `numFailedTests` 1, verbatim `AssertionError: expected +0 to be 1 // Object.is equality` |
| SUCCESS-path CONTROL: same swap, same middleware, `next` returns a Response | exit 0, the swap intercepts EXACTLY ONE chunk |
| Differential typecheck with the spec present | `tsc --noEmit --strict --skipLibCheck` exit 0, zero new errors |

The control is what licenses reading the red as the behaviour gap rather than as a dead observation
mechanism. Without it, a spy that never sees anything would produce an identical red.

**Why the gap is a genuine defect and not a design choice:** `loggerMiddleware`'s handler is
`async (req, next) => { const start = ...; const res = await next(); ...; emit(line); return res; }`
(`src/log.ts:229-239`). When `next()` rejects the await throws and `emit` is never reached, so the
requests missing from the access log are exactly the failed ones. srvx's own `errorPlugin`
(`src/_plugins.ts:4`) unshifts itself AHEAD of the logger, so configuring an error handler converts
the error to a Response only after the rejection has already passed through the logger and does not
restore the line.

## Instrument hazards, recorded not fixed

1. **Line-scoped added-test attribution (deliberate, UNFIXED).** `addedTestTitles` /
   `DIRECT_TITLE_RE` in `grade-red.mjs` match a title literal only on the same source line as its
   `it(` / `test(` call. A correct answer whose title wraps grades `unattributable`. It cost 1 of 9
   runs on the archived SRVC cell. **Read an `unattributable` cluster on either prompt as an
   instrument artifact first and an arm effect second**, and read `changed_production_files` anyway:
   it is recorded on that path too. Both prompts pin the produced test's shape no more than `r1` does
   -- they name the landing directory and nothing else -- so nothing here mitigates it and nothing
   here makes it worse.

2. **Treatment stall, and it is ASYMMETRIC.** The treatment artifact's hard rule is to ASK WHICH SIDE
   before answering, and an apply run is one-shot with nobody to ask. A treatment-arm run that asks
   and edits nothing produces an empty diff, and `assertReadableDiff` then THROWS rather than scoring
   "no change" -- so there is no `red-grade.json` for that run at all. Only the treatment arm carries
   the ask rule, so this cannot be treated as neutral noise. **Count empty-diff runs as their own
   per-arm outcome.** An arm that refuses to answer must not be scored as if it had.

3. **Throw-variant split on `a1`.** A correct answer that writes a not-implemented throw instead of a
   placeholder body is right on the DISCRIMINATOR (NON-EMPTY) but grades `wrong_reason`, because the
   runner failure is a runtime error. The shipped SKILL.md calls that "a valid but blunter red", so
   it is expected, not a bug. Read the discriminator first and the verdict second.

4. **Prompt asymmetry, forced.** `a2` names `src/log.ts`; `a1` names no source file, because `a1`'s
   subject does not exist. It cannot bias the A/B (all three arms get byte-identical bytes) but it
   does mean `a1`'s prompt is less grounded in the tree than `a2`'s. Relevant to a cross-prompt
   comparison, irrelevant to a cross-arm one.

5. **`src/` is a forbidden token on `AMB1` on purpose.** Naming a source directory would resolve the
   artifact's axis 1 syntactically and dissolve the ambiguity. Crux 2 forces the prompt to name the
   landing directory, so `test/` is named and no source directory is -- that asymmetry is inherent to
   the cell, not an oversight.

## Open, not resolved

1. **No srvx analogue of the radix target-config-equality assertion.** `AMB1` and `AMB2` share
   SRVC's machine-readable `runner` and `typecheck` keys byte-for-byte on purpose, which is what
   licenses the existing `crux 7:SRVC` canary pair to cover them, but nothing in `selfcheck-red`
   enforces that for this suite the way `checkRadixTargetConfigEquality` does for radix. The
   `_note` fields deliberately DIVERGE (copying SRVC's `runner_measured` figures down would read as a
   measurement of the new targets), so a naive `JSON.stringify` equality check would fail today. If
   such an assertion is ever added it needs to compare the machine-readable keys only.
2. **The prior doc's cheap recommendation is still undone:** SRVC's own `targets.json` entry does not
   record its measured `no_skill` 3/3 baseline saturation. My `suite.json` note states the fact next
   to it, which is not the same as recording it on the target.
3. **`a1`'s coach-don't-drive confound is not removable within this design.** Separating "declined
   because it read the word test-side" from "declined because lz-red says green is lz-tpp's job"
   needs the answer text, and this cell is mechanically graded by construction (kill 4). If that
   separation matters, it needs a second, non-scoring read of `answer.md`, declared before the run.
4. **Empty-diff / treatment-stall runs have no automatic tally.** `grade-red` throws on them, so the
   operator has to count them by hand from the run directories. If the treatment arm stalls at any
   rate above noise, that IS the finding and it needs recording as such rather than as missing data.
