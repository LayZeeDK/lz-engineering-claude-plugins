## Warnings

### WR-01: check-no-new-js test runs git against an inherited GIT_DIR / GIT_INDEX_FILE

**File:** `.claude/skills/lz-refactor-workspace/tools/check-no-new-js.test.ts:69-71, 84, 90, 92`
**Issue:** `git()` and `listWorkspaceFiles(repo)` call git with `cwd: repo` and the parent's environment.
git ranks `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` above `cwd`, and git hooks and some git
subcommands export them. Both cases were reproduced against scratch repositories:

- `GIT_DIR=<other repo>/.git node --test tools/check-no-new-js.test.ts`: the test's `git init` re-initialised
  the OTHER repository and set `core.bare = true` in its config. After that, `git status` there fails with
  "this operation must be run in a work tree". A normal `git init` writes `bare = false`, so the test caused
  the change.
- `GIT_INDEX_FILE=<file> node --test ...`: the test passed and wrote
  `.claude/skills/x-workspace/staged.mjs` (the empty blob) into that index file. Inside a pre-commit hook,
  that file is the index of the commit being made.

No hook runs `npm run check` today, so this is not a blocker. Once one does, the test damages the real
repository.
**Fix:** Clear git's location variables for the test process before any git call, at the top of the test
file:

```ts
for (const key of ['GIT_DIR', 'GIT_WORK_TREE', 'GIT_INDEX_FILE', 'GIT_OBJECT_DIRECTORY', 'GIT_COMMON_DIR']) {
  delete process.env[key];
}
```

This covers `listWorkspaceFiles` as well, and its production signature stays the same.

### WR-02: Type-check accepts ES2025 APIs that crash on Node.js 22

**File:** `.claude/skills/lz-red-workspace/tsconfig.tools.json:8-9`, `.claude/skills/lz-refactor-workspace/tsconfig.tools.json:8-9`
**Issue:** The scripts must run on Node.js 22 and 24, but `"lib": ["es2025"]` together with `@types/node`
24.19.2 type-checks against Node.js 24. A probe under the same compiler options (TypeScript 6.0.3) that uses
`RegExp.escape`, `Promise.try` and `Float16Array` gives `tsc` exit 0. On Node.js 22.23.1 all three are
`undefined`; on 24.22.0 they are functions. A later script that uses any of them passes `npm run check` on
Node.js 24 and throws a TypeError on Node.js 22. The same gap applies to Node.js APIs added in 23 or 24,
because the `@types/node` major is 24.
**Fix:** Set `"lib": ["es2024"]` in both files. Both tool sets already pass `tsc -p tsconfig.tools.json
--lib es2024` (checked, exit 0). To cover Node.js APIs too, pin `@types/node` to the 22 line, or note in a
comment that `@types/node` follows the newest supported Node.js major.

### WR-03: The guard misses .cjs, so a ported script can come back as CommonJS

**File:** `.claude/skills/lz-refactor-workspace/tools/check-no-new-js.ts:11`
**Issue:** `/^\.claude\/skills\/[^/]+-workspace\/.*\.m?js$/i` matches `.js` and `.mjs` but not `.cjs`, which
is also JavaScript. The script bar (TypeScript, never JavaScript, for a script that stays) is meant to stop
new JavaScript scripts. `x.cjs` passes the guard, and no test covers it.
**Fix:** `const workspaceScript = /^\.claude\/skills\/[^/]+-workspace\/.*\.[cm]?js$/i;`. Add
`${workspace}/x.cjs` to the "reports a .js the same way" test. Then update the header comment and the
first line of grandfathered-js.txt (".mjs/.js").

### WR-04: Glob-based `node --test` passes with zero tests

**File:** `.claude/skills/lz-red-workspace/package.json:8`, `.claude/skills/lz-refactor-workspace/package.json:8`
**Issue:** The old lz-red script named its test file (`node --test cycle-logs.test.mjs`), so a missing file
failed the check. The new form, `node --test "*.test.ts" "tools/**/*.test.ts"`, exits 0 when no file
matches: on Node.js 22.23.1 and 24.22.0, a pattern with no matches reports `tests 0` and exits 0. Today
`tools/**/*.test.ts` matches nothing in lz-red-workspace and `*.test.ts` matches nothing in
lz-refactor-workspace. If `cycle-logs.test.ts` is renamed, moved or deleted, the lz-red check stays green
with no tests run.
**Fix:** Name the test files in each script, as the old one did. For example, in lz-red:
`node --test cycle-logs.test.ts`. In lz-refactor:
`node --test tools/check-erasable-ts.test.ts tools/check-no-new-js.test.ts`. Otherwise keep the globs and
drop the patterns that match nothing, accepting that the step passes when every test file is gone.

## Info

### IN-01: Node.js 22.18 minimum is implied but not declared; below it the guard can pass silently

**File:** `.claude/skills/lz-refactor-workspace/tools/check-no-new-js.ts:47` (same pattern at `check-erasable-ts.ts:165`)
**Issue:** Running .ts without a flag and `import.meta.main` both arrived in Node.js v22.18.0 (Node.js docs at
tag v22.18.0: esm.md, `import.meta.main`, added v22.18.0). Neither package.json declares that minimum. On
22.6 to 22.17 with `--experimental-strip-types` (for example through `NODE_OPTIONS`), `import.meta.main` is
`undefined`, so the main block is skipped. The guard then prints nothing and exits 0.
**Fix:** Add `"engines": { "node": ">=22.18" }` to both package.json files. Optionally make the entry
check fail loudly: `if (typeof import.meta.main !== 'boolean') { throw new Error('Node.js >= 22.18 required'); }`.

### IN-02: A grandfathered file deleted but not staged is not reported as stale

**File:** `.claude/skills/lz-refactor-workspace/tools/check-no-new-js.ts:39`
**Issue:** `--cached` keeps listing a tracked file after it is deleted from the working tree, so its
grandfather line is reported stale only after `git rm`. A plain `rm` of a ported .mjs passes the guard
until the deletion is staged. Low risk, since the commit that ports the script normally stages the
deletion.
**Fix:** Check `existsSync(join(repoRoot, path))` for each listed path, or add `--deleted` and drop those
paths from the listing.

### IN-03: cycle-logs tests leave documented behaviour untested and depend on test order

**File:** `.claude/skills/lz-red-workspace/cycle-logs.test.ts:30-62`
**Issue:** The module comment promises behaviour that no test checks: the `node_modules` exclusion, the
`.txt` and `.log` extensions beside the run folder, and the dangling-symlink skip that is the stated reason
for `lstat`. Also, the first test's exact `deepEqual` holds only because the later tests create their files
afterwards in the same shared folder. Reordering the tests or running them concurrently breaks it. This was
carried over from the .mjs test, so it is not a regression.
**Fix:** Add one case that writes `b-1/node_modules/x/cycle.md` and `b-1.run-log.txt` and asserts that only
the second is credited. Give each test its own run folder (`b-1`, `b-2`, ...) so the tests stop sharing
state.

### IN-04: check-erasable-ts blanks code after an apostrophe in tsx text

**File:** `.claude/skills/lz-refactor-workspace/tools/check-erasable-ts.ts:84-104`
**Issue:** A `'` or `"` string is read until the next matching quote, across newlines. In a tsx fence, JSX
text such as `<p>Don't</p>` therefore blanks every following line up to the next `'`, which hides any
parameter property in that range. This only causes false negatives, and the existing `shortcut:` comment
names regex literals and template `${}` but not this case.
**Fix:** For `'` and `"` (not backtick), end the string at a newline, as JavaScript does: stop the inner
loop at `\n` and leave the newline for the outer loop, without emitting a closing quote. Otherwise add this
case to the `shortcut:` comment.
