## Implementation Decisions

All four decisions below are LOCKED. They were settled with the owner before planning; do not
re-litigate them.

### D-01: Route on INTENT, never on test state (LOCKED)

The new lz-red branch keys on what the user is ASKING FOR, stated positively. It must NOT branch
on whether a failing test currently exists.

**This is the decisive constraint of the task.** The rejected phrasing -- "no failing test in hand
yet -> lz-red" -- has a proven defect: that condition is TRUE for a user who wants to clean up
passing code, so the negative catch-all strictly contains the cleanup branch and every
cleanup-on-green request mis-routes to lz-red.

The defect is WORSE here than where it was first found. It shipped in lz-tpp
(`51f76c2`), survived Phase 18's own verification, and was caught only later by a from-scratch
unbiased reviewer; `50fb4ba` fixed it. **Cleanup-on-green is lz-refactor's PRIMARY use case**, so
the same wording here would misfire on the most common request the skill receives.

### D-02: WIDEN the existing section; do not add a parallel one (LOCKED)

`## Refactoring vs the green step (the lz-tpp seam)` already exists at line 37 and already feeds
step 1 at line 45. Widen it to cover both siblings and rename the heading accordingly.

This DEPARTS from the SEAM-02 precedent (`50fb4ba` was strictly additive, +10/-0). That precedent
does not transfer: lz-tpp had no existing sibling-seam section, so additive was its only option.
lz-refactor has one, and appending a second would leave two adjacent "how this differs from the
other steps" blocks for a reader to reconcile.

Accepted tradeoff: widening edits reviewed prose rather than appending to it, so the regression
surface is slightly larger. The existing lz-tpp routing inside the section must survive intact --
the change is additive WITHIN the section.

### D-03: Mirror the corrected lz-tpp SHAPE, not its text (LOCKED)

Reuse the decision structure and the intent-keying principle from the corrected lz-tpp pointer.
Write the prose from lz-refactor's own vantage -- a verbatim copy reads wrong, because
lz-refactor's "stay here" branch is the refactor step, not the green step.

### D-04: Guard must be mutation-tested in BOTH directions (LOCKED)

Exit 1 with the pointer stripped, exit 0 with it present. A guard that only passes proves nothing.
Follow the SEAM-02 guard precedent, which bumped `EXPECTED_CHECKS` and was mutation-tested the
same way.
